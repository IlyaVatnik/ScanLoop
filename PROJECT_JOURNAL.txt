--- ЧТО СДЕЛАНО ---

1. Архитектура: _BSMConnection (общий для каналов) + ThorlabsBSM (по каналу)
   - Реф-счётчик, общий USB для обоих каналов

2. Инициализация (_BSMConnection.__init__):
   - TLI_BuildDeviceList → SBC_Open (с retry) → SBC_LoadSettings(каналы 1,2)

3. Инициализация (ThorlabsBSM.__init__):
   - log_channel_status → SBC_StartPolling → SBC_EnableChannel (250ms wait)
   - InputVoltage check → SetBacklash(0) → SetVelParams(maxVel=2.0mm/s, accel=0.5mm/s²)
   - Если позиция < 0: CanMoveWithoutHomingFirst → reset counter / homing

4. Homing:
   - set_homing_velocity: ставит 5mm/s если текущая <50% нужной
   - move_home: опрос по HOMING биту (bit 7=0x80) + 5с таймаут без движения + 30с общий
   - Homing в __init__: тот же подход

5. move_relative:
   - Статус-биты → StartPolling → ClearMessageQueue → SetMoveRelativeDistance → MoveRelativeDistance
   - Polling: simple stable_count (позиция 0.0 валидна!)

6. get_position:
   - RequestPosition → GetPosition → raw * ENCODER_STEP → mm
   - Отрицательные raw → возвращаем 0.0 с WARNING

7. Тесты: 24 (scan 3, init 5, velocity 4, move_relative 4, channel_init 5, KDC 3)

--- КЛЮЧЕВЫЕ ОТКРЫТИЯ О THORLABS BSM ---

1. ПОСЛЕДОВАТЕЛЬНОСТЬ ИНИЦИАЛИЗАЦИИ:
   Open → LoadSettings → StartPolling → EnableChannel → Home → SetVelocity → Move

2. SBC_LoadSettings: возвращает False даже при успехе (баг DLL), не проверять

3. SBC_EnableChannel: ОБЯЗАТЕЛЕН — без него команды движения ИГНОРИРУЮТСЯ

4. SBC_SetHomingVelocity: дефолт firmware ~1mm/s, нужно ставить явно

5. HOMING bit = bit 7 (0x80) статус-бита — использовать вместо pos==0

6. ERROR flag 0x80101000: bit 12 может быть не ошибкой для BSM
   (pylablib: bit 12 = "tracking", не ERROR)

7. SBC_PersistSettings: НЕ вызывать (Kinesis перезаписывает)

8. Каналы BSM: 1-based (1, 2, 3...), НЕ 0-based

--- СРАВНЕНИЕ API: KINESIS vs APT vs LABSOFT ---

Наш код (Kinesis API — SBC_* функции):
  TLI_BuildDeviceList → SBC_Open → SBC_LoadSettings → SBC_StartPolling
  → SBC_EnableChannel → check voltage → set velocity → home → move

LabSoft (APT API — MOT_* функции):
  APTInit → EnableEventDlg(False) → InitHWDevice(serial)
  → MOT_SetHomeParams(2,1,7.0,0.0001) → MOT_MoveHome → move

Ключевое различие:
  - APT: InitHWDevice = ОДНА функция (open+load+enable)
  - Kinesis: Open + LoadSettings + StartPolling + EnableChannel = 4 функции
  - LabSoft НЕ вызывает MOT_EnableHWChannel явно
  - LabSoft НЕ вызывает SetPowerParams, SetStageAxisLimits, SetLimitSwitchParams
  - LabSoft СТАВИТ velocity ПЕРЕД каждым move (set_velocity_parameters)

--- КАКИЕ ФУНКЦИИ НЕ ВЫЗЫВАЮТСЯ (Kinesis API) ---

1. SBC_SetPowerParams — move=2-8%, rest=129-130% (нужно move=100, rest=50)
2. SBC_SetLimitsSoftwareApproachPolicy(AllowAllMoves) — убрать SW_LIMIT
3. SBC_SetStageAxisLimits — не установлены min/max позиции
4. SBC_SetLimitSwitchParams — концевики не настроены
5. SBC_StopImmediate / SBC_StopProfiled — не используются

--- ПРОБЛЕМЫ ИЗ ЛОГОВ ---

1. PowerParams: move=2-8% — мотор получает крошечный ток, скорость ~5μm/s
2. InputVoltage ~0.7V — ниже нормы (нужно ≥5V)
3. SW_LIMIT на 0.278mm — программный лимит блокирует движение
4. Homing "мгновенный" — мotor не двигается из-за низкого тока
5. SBC_GetPosition возвращает -27502, -70351 после homing — мусор
6. get_position() маскирует отрицательные raw в 0.0 — скрывает ошибки
7. Error flag 0x80101000 никогда не сбрасывается

Создан Scripts/PairedRecorder.py — QObject в своём потоке (ThreadedMainWindow.add_thread).
Публичный API:
  - set_devices(scope, osa) — идемпотентно; runner для scope создаётся один раз.
  - start_single() — 1 кортеж: 1+1 (оба замера обязательны).
  - start_repeat() — цикл; граница кортежей по циклу OSA (старт -> received_spectrum);
    scope-замеры копятся в текущий кортеж (N:1).
  - stop() — остановка, текущий кортеж сохраняется.
Сигналы: S_print, S_print_error (→ GUI-лог и файл Logs), S_finished, S_running(bool),

    (3 попытки, пауза 1 с, таймаут развёртки 120 с по умолчанию; настраивается в
    конструкторе PairedRecorder: retry_attempts, retry_pause, scope_timeout).
  - Watchdog OSA: QTimer osa_timeout=600 с (по умолчанию). Если спектр не пришёл —
    потеря, кортеж закрывается, в Repeat цикл продолжается.
  - В Repeat при ошибке любого прибора: сохраняется то, что получено, цикл продолжается
